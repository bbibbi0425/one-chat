# one-chat

초대 링크와 닉네임으로 시작하는, 생성 후 **9시간** 동안의 대화방입니다.

## 기능

- 회원가입 없이 방 만들기 → 초대 링크 공유 → 닉네임 입장
- 브라우저 AES-256-GCM 암호화: 닉네임과 메시지 평문은 서버에 전송하지 않음
- D1에 암호문 저장, 약 1초 간격으로 메시지 동기화
- 같은 링크로 재입장하면 만료 전 대화 복원 (닉네임은 다시 입력)
- 전송 실패 시 같은 암호문으로 재시도, 중복 저장 방지, 연결 복구와 이력 페이지 처리
- 서버/DB 시간 기준 9시간 만료: 재입장·전송으로 연장되지 않음
- 만료 즉시 조회·입장·전송 차단, 매분 Cron으로 운영 DB의 만료 데이터 정리

현재는 소스 구현과 로컬 검증 단계이며 **공개 서비스로 배포되지 않았습니다.** GitHub Pages는 정적 호스팅이므로 이 앱의 서버와 DB를 실행할 수 없습니다.

## 로컬 실행

Node.js **24 LTS** 권장 (최소 22.13). React 19 / TypeScript / Vinext / Cloudflare Workers / D1 / Drizzle 기반입니다.

```sh
npm run install:ci
npm run build
npm run db:migrate:local
npm run dev
```

표시된 localhost 주소를 엽니다. 두 탭에서 같은 초대 링크로 들어가 다른 닉네임을 입력하면 됩니다. 외부 DB 계정 없이 로컬 D1을 사용합니다. DB는 Git에서 제외된 `.wrangler/state`에 유지됩니다. 재시작해도 같은 링크의 암호문을 만료 전까지 읽을 수 있습니다.

`npm run db:migrate:local`은 Wrangler의 마이그레이션 이력으로 중복 적용을 방지합니다. 스키마를 변경한 경우 `npm run db:generate` 후 빌드 및 마이그레이션을 실행하세요. 이미 적용한 마이그레이션은 수정하지 않습니다.

프로덕션 빌드의 로컬 확인:

```sh
npm start -- --port 8788 --test-scheduled
node --experimental-strip-types tests/http-smoke.mjs http://localhost:8788
```

로컬 Cron 핸들러는 `http://localhost:8788/__scheduled`를 호출해 확인합니다. 로컬 개발 서버에는 실제 매분 Cron 스케줄러가 없으며, 배포 시 Worker의 매분 Cron 트리거가 활성화되어야 합니다. 방 생성과 만료 접근 시에도 정리를 수행합니다.

## 검증

```sh
npm run typecheck
npm run lint
npm test
npm run build
```

테스트는 SQLite 기반 실제 SQL 실행, 권한 분리, 정확한 만료 경계, 지연된 쓰기의 만료 검사, 동시 재전송 중복 방지, 변조 탐지, 최대 메시지 크기 및 동기화 커서를 검증합니다. `http-smoke.mjs`는 실행 중인 로컬 Worker/D1에서 두 참가자의 암호화 대화를 확인합니다. 실제 브라우저 클릭·화면 검증은 별도입니다.

GitHub Actions도 타입 검사·린트·테스트·빌드를 실행합니다. 호스팅 배포는 자동으로 실행하지 않습니다.

## 파일 구조

- `app/page.tsx`: 방 생성/입장, 초대, 채팅, 만료 화면
- `lib/crypto.ts`: 키 가져오기, AES-GCM, 초대 링크 해석
- `lib/server.ts`: 권한 확인, 저장·조회, DB 시간 만료, 요청 한도
- `lib/sync.ts`: 이력 페이지 및 커서 처리
- `db/schema.ts`, `drizzle/`: DB 스키마와 버전별 마이그레이션
- `worker.ts`: 응답 보안 헤더와 주기적 만료 삭제
- `tests/`: 암호화·API·동기화 자동 검증

## 개인정보와 보관 범위

초대 링크의 `#` 뒤 fragment에는 서로 독립적인 256비트 접근 토큰과 암호화 키가 있습니다. fragment는 일반 HTTP 요청 URL에 포함되지 않습니다. 입장 시 접근 토큰만 API로 전송하며, 서버는 해시만 저장합니다. 입장 후 방에 한정된 세션 토큰으로 읽기·쓰기를 인증합니다. 암호화 키는 브라우저에서만 사용합니다.

메시지는 매번 무작위 96비트 IV를 쓰며 방 ID·참가자 ID·메시지 ID를 AAD로 묶습니다. 닉네임은 인증된 신원이 아니며, 공유 키를 가진 참가자는 누구나 대화를 읽을 수 있습니다. 링크를 아는 사람은 기존 대화도 읽을 수 있고 링크를 잃으면 복구할 수 없습니다. 키 교체/순방향 비밀성은 제공하지 않습니다.

앱은 메시지·닉네임·키를 localStorage/sessionStorage에 저장하지 않습니다. 새로고침 후에는 같은 링크로 다시 입장하고 닉네임을 다시 입력합니다. 주소창, 브라우저 기록, 클립보드, 화면, 상대방 복사본에는 링크나 평문이 남을 수 있습니다. 방 나가기는 현재 탭의 앱 상태와 주소에서 링크를 지우며, 브라우저/운영체제의 모든 흔적을 지우는 기능은 아닙니다.

**9시간 만료는 접근 차단 시각입니다.** 운영 DB 정리는 매분 작업으로 수행되므로 실제 삭제는 스케줄 실행 지연만큼 늦어질 수 있습니다. D1의 [Time Travel 백업](https://developers.cloudflare.com/d1/reference/time-travel/)은 항상 활성화되어 암호문 사본이 운영 DB 삭제 후에도 남을 수 있습니다. 모든 사본의 즉시 완전 삭제를 보장하지 않습니다.

서비스 운영자는 방·참가자 ID, 시간, 암호문 길이 등 메타데이터를 볼 수 있습니다. 서비스 코드 또는 기기가 변조되면 브라우저 암호화도 보호를 보장하지 못합니다. 회사 기기의 모니터링, 화면/키 입력 수집, 네트워크 접속 기록을 숨기는 서비스가 아닙니다.

외부 분석·광고·폰트·메시지 알림 서비스는 사용하지 않습니다. 요청 본문/인증 헤더/초대 링크를 로그에 남기지 않습니다. 프록시·호스팅 제공자의 로그 정책은 별도 확인이 필요합니다. 응답에 `no-store`, `no-referrer`, 프레임 방지, 외부 리소스 제한 정책을 적용합니다. CSP는 프레임워크 hydration을 위해 inline script를 허용하므로 XSS를 완전히 차단하는 장치로 보지 않습니다. 메시지는 React 텍스트로 렌더링합니다.

## 사용 한도

소규모 사용을 위해 활성 방 10개, 방당 메시지 2,000개, 메시지 2,000자, 닉네임 20자, 방당 분당 전송 120개를 제한합니다. 방당 입장 세션 256개이며 새로고침·재입장도 세션을 사용합니다. 세션은 방 만료 시 함께 삭제합니다. 분 단위로 해시한 IP 기반 생성/입장 제한 기록은 약 2분 후 삭제 대상이 됩니다. 같은 회사 NAT 사용자는 이 제한을 공유할 수 있습니다. 이 한도는 외부의 대규모 트래픽 방어를 대신하지 않습니다. 방 생성 API가 익명 공개 상태이므로 제3자가 활성 방 한도를 소진할 수 있습니다. 인터넷 공개 배포 전에는 생성자 접근 제한 또는 호스팅 측 생성 요청 보호를 반드시 구성해야 합니다.

## 배포 시 설정

GitHub 푸시만으로 채팅 서비스가 생기지는 않습니다. 별도의 HTTPS 앱 호스트, D1 DB 바인딩 `DB`, 마이그레이션 적용, `worker.ts`의 scheduled 핸들러와 `* * * * *` Cron이 필요합니다. 프로젝트의 `.openai/hosting.json`은 논리 바인딩을 선언하며 실제 DB ID/배포 계정은 아직 연결하지 않았습니다. `vite.config.ts`의 DB ID는 로컬 개발용 자리표시자입니다.

포트폴리오와 **다른 origin**에 배포하세요. 공개 대규모 서비스로 운영하기 전에는 생성/입장 엔드포인트의 호스팅 측 요청 제한과 리소스 할당량을 설정하세요. 환경변수/토큰은 `.dev.vars*`, `.env*` 등 Git 제외 파일이나 호스팅의 비밀값 저장소에만 보관하세요.

지원 브라우저에서는 선택적인 WebMCP `get_room_status`가 연결 여부와 만료 시간만 반환합니다. 키·초대 링크·메시지는 노출하지 않습니다. 미지원 브라우저에서는 비활성화됩니다. 이 실험적 브라우저 도구 등록은 현재 환경에서 실행 검증하지 않았습니다.
