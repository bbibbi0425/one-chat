# one-chat

닉네임과 초대 링크로 연결하는 **두 사람 전용 일회성 채팅**입니다. GitHub Pages에서 실행할 수 있는 React · TypeScript · Vite 정적 앱이며, 직접 운영할 채팅 서버나 DB가 없습니다.

## 사용하기

1. 사이트에서 닉네임을 입력하고 **방 만들기**를 누릅니다.
2. **링크**를 눌러 함께할 한 사람에게 공유합니다. 방을 만든 사람은 창을 열어 둡니다.
3. 상대방이 링크를 열고 닉네임을 입력합니다. 둘 다 **연결됨**이면 대화할 수 있습니다.
4. 메시지의 **전달됨**은 상대 앱의 수신 확인이며 읽음 표시가 아닙니다.
5. 나가기, 새로고침, 데이터 연결 종료 또는 생성 후 최대 9시간에 방이 끝납니다. 이전 대화는 다시 불러올 수 없습니다. 감지에는 최대 약 3분이 걸릴 수 있고 브라우저가 일시 중지되면 더 늦어질 수 있습니다.

상단 **기본 / 메모**에서 화면을 전환합니다. 메모 테마는 말풍선 대신 왼쪽 정렬된 문서 형태로 표시하고 탭 제목·아이콘과 입력창을 바꿉니다. 전환해도 연결, 대화, 작성 중인 글은 유지됩니다. 선택은 브라우저 저장소에 기록하지 않습니다. 일반 접속은 기본 테마로 시작하고, 작은 창은 열 때 선택한 테마를 URL의 화면 설정으로 전달받습니다. 화면 표현만 바꾸므로 접속 기록을 숨기는 기능은 아닙니다.

대화와 입력창의 기본 글자 크기는 **14px**입니다. 상단 **A− / A+**로 **12~20px** 사이에서 1px씩 조절하며, 가운데 숫자가 현재 크기입니다. 기본·메모 테마와 작은 창 모두 지원하고 내 화면에만 적용됩니다. 조절해도 연결, 작성 중인 글, 읽던 메시지 위치를 유지합니다. 선택은 브라우저 저장소에 기록하지 않으며, 새로 연 작은 창에는 선택한 크기를 전달합니다. 브라우저의 기본 글자 크기와 확대 설정도 반영합니다.

상단 **창**에서 사용 방식을 선택합니다.

- **현재 창에서 계속:** 일반 브라우저 화면을 그대로 사용합니다.
- **작은 창 열기:** 입장 전에 누르면 약 400 × 560 크기의 별도 창을 요청합니다. 현재 테마·글자 크기와 대기 중인 초대를 이어받고 이름은 새 창에서 입력합니다. 초대 키는 여전히 URL fragment에만 전달합니다. 진행 중인 방을 옮기거나 다시 연결하지 않으며, 이미 열린 작은 창이 있으면 그 창으로 돌아갑니다. 원래 입장 전 탭은 닫아도 됩니다. 브라우저 설정에 따라 팝업 차단, 새 탭 열기 또는 주소 표시줄 유지가 가능합니다.
- **Chrome 앱 창:** 메뉴에 표시된 `⋮ → 전송, 저장 및 공유 → 페이지를 앱으로 설치…` 안내를 따라 직접 설치하면 탭·주소창·북마크 바 없는 앱 창으로 사용할 수 있습니다. 제목 표시줄은 남을 수 있고, 시크릿 모드·관리 정책에 따라 설치가 제한될 수 있습니다. 설치와 창 이동은 대화 시작 전에 하세요. 초대받은 링크를 앱 창으로 옮기는 기능은 없으므로 앱 창을 사용할 사람이 방을 만든 뒤 초대하는 방식이 편합니다.

일반 화면·팝업·앱 창은 선택 사항입니다. 새로고침이나 창 닫기로 끝난 대화는 복구하지 않습니다. [Chrome 앱 설치 안내](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DDesktop&hl=ko) · [팝업의 브라우저별 제한](https://developer.mozilla.org/en-US/docs/Web/API/Window/open)

입력창 옆 **스티커** 버튼을 열고 그림을 한 번 눌러 선택한 뒤, **같은 그림을 다시 누르면 바로 전송**합니다. 빠르게 연속해서 누르지 않아도 됩니다. 선택창을 닫거나 다른 그림을 고르면 다시 두 번 눌러야 합니다. 쓰던 글은 그대로 남습니다. 제공된 그림 6종을 사용하며 업로드나 외부 이미지 검색은 없습니다.

**화면과 앱 상태에는 텍스트와 스티커를 합쳐 최근 50개만 유지합니다.** 새 메시지로 한도를 넘으면 가장 오래된 내용을 제거하며, 위로 스크롤해도 다시 불러올 수 없습니다. 이 정리는 방이나 연결을 종료하지 않습니다. 메시지를 입력하지 않아도 자동 연결 확인은 계속됩니다.

두 사람이 동시에 접속해야 합니다. 오프라인 전송, 재입장, 이력 복구, 그룹 채팅은 지원하지 않습니다. 새 대화에는 새 방과 링크를 사용하세요.

## 로컬 실행

Node.js **24 LTS** 권장 (최소 22.13).

```sh
npm run install:ci
npm run dev
```

표시되는 `http://127.0.0.1:5173` 주소를 열어 두 탭에서 먼저 확인할 수 있습니다. 다른 컴퓨터에서는 localhost 초대 링크를 사용할 수 없으므로 배포된 HTTPS 주소를 사용하세요. API 키, DB 설정, 환경변수는 필요하지 않습니다.

프로덕션 빌드 확인:

```sh
npm run build
npm start
```

## GitHub Pages 배포

빌드 결과인 `dist/`를 배포합니다. 상대 경로를 사용하므로 `/one-chat/` 같은 프로젝트 경로를 지원합니다.

1. 저장소 **Settings → Pages → Build and deployment → Source → GitHub Actions**를 선택합니다.
2. **Actions → Deploy GitHub Pages → Run workflow**를 실행합니다.
3. 이후 main 푸시마다 배포하려면 **Settings → Secrets and variables → Actions → Variables**에서 `PAGES_ENABLED`를 `true`로 추가합니다.
4. 성공한 배포가 표시하는 주소로 접속합니다. 기본 프로젝트 주소는 `https://bbibbi0425.github.io/one-chat/`입니다. 배포 전에는 이 주소가 동작하지 않습니다.

GitHub Free에서는 공개 저장소에 Pages를 사용할 수 있습니다. 비공개 저장소는 Pages를 지원하는 유료 플랜이 필요합니다. 저장소 공개 전환은 코드와 커밋 기록을 공개하는 별도 결정입니다. 이 프로젝트가 자동으로 공개 전환을 하지는 않습니다. [GitHub Pages 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

Pages의 웹 화면과 정적 코드는 방문자에게 공개됩니다. 무작위 초대 링크와 키는 실행 시 브라우저에서 생성되며 저장소에 저장되지 않습니다. 공개 초기 화면을 아는 것만으로 기존 방에 참여할 수는 없습니다.

한 방에는 각자 최대 2,000개까지 전송할 수 있고 메시지당 2,000자, 닉네임 20자입니다. 대량 전송 시 한 번에 수신 확인을 기다리는 메시지는 64개로 제한합니다.

## 연결 방식과 한계

- **GitHub Pages:** HTML · CSS · JavaScript 배포.
- **PeerJS Cloud (`0.peerjs.com`):** 두 브라우저가 연결 정보를 교환하는 외부 시그널링 서비스. 자체 서버 구축이나 계정은 필요 없지만 서비스 가용성에 의존합니다. 메시지 평문, 닉네임, 초대 키를 시그널링 데이터에 넣지 않습니다.
- **Google STUN (`stun.l.google.com:19302`):** 직접 연결에 필요한 네트워크 주소 확인.
- **WebRTC DataChannel:** 실제 대화 전송. 암호화된 채널 위에서 앱의 초대 키 인증과 메시지 암호화를 추가합니다.

TURN 중계는 설정하지 않았습니다. 따라서 일부 회사망·방화벽·NAT 환경에서는 연결할 수 없습니다. GitHub Pages에 화면이 열린다고 채팅 연결까지 보장되는 것은 아닙니다. 시그널링 연결이 잠깐 끊겨도 이미 성립한 데이터 채널은 유지합니다. 실제 데이터 연결이 끝나면 새 방을 만들어야 합니다.

[PeerJS Cloud](https://peerjs.com/server/cloud) · [WebRTC 연결과 STUN/TURN](https://webrtc.org/getting-started/peer-connections)

## 개인정보와 보관 범위

메시지는 탭의 메모리에 최근 50개만 남깁니다. 타이머와 입력창은 대화 목록과 분리되어, 초 단위 갱신이나 입력 때 전체 목록을 다시 처리하지 않습니다. 메시지 시간은 추가될 때 한 번 계산하고 변경되지 않은 행은 재사용합니다. 앱은 대화·닉네임·키를 서버 DB, localStorage, sessionStorage, IndexedDB에 기록하지 않습니다. 연결 종료 시 화면과 앱 상태를 비웁니다. 브라우저나 운영체제 메모리의 물리적 완전 삭제를 보장하지 않습니다.

초대 링크의 `#` 뒤에는 호스트 ID, 256비트 무작위 비밀 키, 만료 시간이 있습니다. fragment는 일반 HTTP 요청 URL에 포함되지 않으며, 읽은 뒤 주소창에서 제거합니다. 공유한 링크·클립보드·브라우저 기록·상대방의 복사본은 별도로 남을 수 있습니다. 닉네임은 실명 인증이 아닙니다. 링크를 가진 첫 유효 참가자가 상대방이므로 믿을 수 있는 경로로 한 사람에게만 전달하세요.

호스트와 게스트의 실제 Peer ID, 만료 시간, 양측의 새로운 난수와 프로토콜 버전을 묶어 HMAC-SHA256으로 서로 키 소유를 확인합니다. 이 세션 정보에서 HKDF-SHA256으로 방향별 AES-256-GCM 키를 파생합니다. 방향마다 순번 IV와 인증된 세션 정보를 사용하고 중복·역순 프레임은 거부합니다. 새 세션은 새로운 난수를 쓰며, 닉네임도 인증 후 암호화해서 보냅니다. 앱의 공유 키 방식 자체는 순방향 비밀성을 제공하지 않습니다.

9시간 제한은 벽시계와 단조 시계로 **정상 앱에서** 적용합니다. 서버가 강제하는 만료나 악의적인 상대의 사본 삭제 기능은 아닙니다. 탭을 닫거나 연결이 끝나면 9시간 이전에도 대화가 끝납니다.

호스팅·시그널링·STUN 제공자와 회사 네트워크는 IP·접속 시각 등의 정보를 볼 수 있습니다. GitHub Pages는 방문자 IP를 기록합니다. 회사 기기의 기록 수집, 화면·키 입력 수집, 변조된 브라우저나 배포 코드, 상대방의 저장을 막거나 숨기지 못합니다. **회사에 아무 기록도 남지 않는 서비스는 아닙니다.**

외부 분석·광고·폰트·알림 스크립트는 사용하지 않습니다. PeerJS도 npm 패키지로 빌드에 포함합니다. 메시지는 HTML로 해석하지 않습니다. 정확히 일치하는 등록된 스티커 코드만 고정된 로컬 이미지로 표시하고, 나머지는 React 텍스트로 표시합니다. 스티커도 기존 암호화·수신 확인·전송 한도를 사용하며 이미지 파일 자체를 대화로 보내지 않습니다. 업데이트 전부터 열어 둔 상대 탭에는 스티커 코드가 텍스트로 보일 수 있으므로, 새 방을 만들기 전에 둘 다 최신 화면을 여세요. 그림 6종은 처음부터 앱 번들에 함께 포함해, 어떤 스티커를 주고받는지에 따라 개별 이미지 HTTP 요청이 발생하지 않습니다. 이 정적 자산은 공개된 사이트 코드의 일부이며 브라우저가 캐시할 수 있습니다. 프로덕션 HTML에는 제한된 CSP와 no-referrer를 적용합니다. GitHub Pages에서는 임의의 응답 헤더를 설정하지 못하므로 서버 버전의 no-store·프레임 방지 헤더를 제공한다고 주장하지 않습니다. `noindex`는 접근 통제가 아닙니다.

## 검증

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run test:build
```

실제 Web Crypto로 상호 인증, 잘못된 키, 변조·재전송 방지, 동시 전송, 수신 확인, 만료, 종료 중 비동기 작업을 검증합니다. 가짜 Peer 연결로 두 사람 제한, 잘못된 초대 후 복구, 시그널링 장애, 종료와 정적 빌드 경로를 검사합니다. **이 자동 테스트는 실제 브라우저 간 WebRTC/NAT 연결 성공을 검증하지 않습니다.** 사용하려는 네트워크에서 두 브라우저로 직접 연결·송수신·나가기 확인이 필요합니다.

GitHub Actions는 타입 검사·린트·테스트·정적 빌드를 확인합니다. Pages 배포는 위 설정 이후 실행합니다.

## 주요 파일

- `app/page.tsx`: 초대, 닉네임, 연결 상태와 방 수명 관리
- `components/chat/`: 독립된 타이머·입력창과 메시지 목록
- `lib/stickers.ts`, `assets/stickers/`: 고정 스티커 목록·사용자 제공 원본 PNG
- `lib/transcript.ts`: 최근 50개 유지, 수신 확인, 표시 시간 캐시
- `lib/peer-chat.ts`: PeerJS 연결, 두 사람 제한, 연결 종료
- `lib/secure-session.ts`: 인증과 암호화 메시지 세션
- `lib/crypto.ts`, `lib/protocol.ts`: 암호화·초대·프레임 검증
- `.github/workflows/pages.yml`: GitHub Pages 정적 배포

기존 Worker/API/DB/마이그레이션 코드는 제거했습니다. 이전 버전에서 만들어진 로컬 `.wrangler/state`는 새 앱이 읽거나 사용하지 않습니다. 원래 템플릿의 일부 미사용 의존성은 남아 있지만 런타임 서버나 DB가 필요하다는 의미는 아닙니다.

지원 브라우저의 선택적 WebMCP `get_room_status`는 연결 여부와 만료 시간만 반환하며 키·링크·닉네임·메시지를 노출하지 않습니다. 이 실험적 등록은 실제 브라우저에서 별도 검증하지 않았습니다.
